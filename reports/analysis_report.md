## 1. 한 줄 결론

**물리 기반으로 생성한 CNC 설비 합성 데이터에서 30분 내 고장을 시간순 평가한 결과 PR-AUC 약 0.76을 확인했으며, 동일한 데이터와 모델을 랜덤 split으로 평가하면 PR-AUC가 0.9819까지 상승했습니다.
예지보전에서는 모델 성능 자체뿐 아니라 시간적 의존성을 고려한 평가 방법이 중요하다는 것을 확인했습니다.**

## 3. 데이터와 방법

### 3.1 데이터

| 출처 | 규모 | 역할 |
|---|---|---|
| 자체 시뮬레이터 | 오염 후 55,591행 | 수집·정제·누수·드리프트 등 파이프라인 검증 |
| UCI AI4I 2020 | 10,000행 × 14열 | 불균형 데이터와 이상치 처리 검증 |
| UCI SECOM | 1,567행 × 590센서 | 고차원·저표본·분포 이동 검증 |

**시뮬레이터 데이터는 합성 데이터입니다.**

실제 설비 데이터라고 가정하지 않고, 참값을 알고 있는 데이터를 만든 뒤
오염을 주입하여 전처리 과정이 원래 신호를 얼마나 복원하는지 검증하는 용도로 사용했습니다.

### 3.2 처리 이력

| 단계 | 행 수 | 증감 | 설명 |
|---|---:|---:|---|
| 0. 원본 수신 | 55,591 | — | 14개 일별 CSV |
| 1~2. 타입 강제·타임스탬프 스냅 | 55,591 | 0 | 시간 형식 통일 |
| 3. 중복 제거 | 53,874 | -1,717 | `(machine_id, ts)` 기준 |
| 4. 단위 통일 | 53,874 | 0 | 센서 단위 통일 |
| 5. 물리범위 위반 → NaN | 53,874 | 0 | 행을 삭제하지 않고 해당 값만 NaN |
| 6. 스파이크 플래그 | 53,874 | 0 | 이상값을 바로 삭제하지 않고 표시 |
| 7. 짧은 결측 보간 | 53,874 | 0 | 짧은 결측만 보간 |
| 8. 드리프트 보정 | 53,874 | 0 | 센서 드리프트 추정 및 보정 |
| 9. 시간축 재색인 | 60,479 | +6,605 | 통신 공백을 명시적인 빈 행으로 표현 |

원본 55,591행에서 중복 1,717건을 제거했습니다.

재색인 과정에서 추가된 6,605행은 새로 만들어낸 센서 데이터가 아니라
**수집되지 않은 시간 구간을 명시적으로 표현한 행**입니다.

피처와 미래 라벨 생성이 가능한 데이터를 추린 뒤 모델 학습에는 53,811행을 사용했습니다.

### 3.3 참값 대비 정제 검증

합성 데이터의 장점은 오염 전 참값을 알고 있다는 것입니다.

따라서 단순히 "전처리가 끝났다"고 판단하지 않고
정제된 값과 원래 참값의 차이를 직접 비교했습니다.

센서별 MAE를 비교한 결과 정제 후 오차가 크게 감소했고,
CNC-02에 주입한 온도 드리프트 역시 실제 0.35 K/day에 가까운 약 0.346 K/day로 추정했습니다.

이를 통해 정제 파이프라인이 단순히 행을 삭제하는 것이 아니라
오염된 센서 신호를 원래 신호에 가깝게 복원하는지 확인했습니다.

### 3.4 모델링

- 예측 목표: **향후 30분 내 고장 여부**
- 원시 센서와 물리 기반 파생변수 및 롤링 통계 사용
- 총 피처 수: 약 100개
- 모델: RandomForest
- 롤링 피처는 미래 데이터를 참조하지 않도록 과거 데이터만 사용
- 실제 예지 평가에서는 시간순 split 사용
- 모델 확률 0.5를 고정하지 않고 비용 기반 임계값을 별도 검증

## 4. 주요 발견

### 4.1 불균형 데이터에서는 정확도만으로 모델을 평가할 수 없다

AI4I의 고장률은 약 3.39%입니다.

모든 데이터를 정상으로 예측해도 정확도는 약 96.6%가 되지만
실제 고장은 하나도 찾아내지 못합니다.

| 모델 | 재현율 | PR-AUC |
|---|---:|---:|
| 무조건 정상 | 0.0000 | 약 0.034 |
| RandomForest | 0.5765 | 0.7886 |
| RandomForest + 파생변수 | 0.8235 | **0.8966** |

따라서 불균형 문제에서는 높은 정확도 자체보다
**PR-AUC와 양성률 기준선 대비 성능**을 함께 확인하는 것이 중요했습니다.

---

### 4.2 시간 누수 — 랜덤 split이 성능을 과대평가할 수 있다

같은 데이터와 모델을 사용하고 split 방식만 변경했습니다.

| split | ROC-AUC | PR-AUC | F1@0.5 |
|---|---:|---:|---:|
| 랜덤 split | **0.9954** | **0.9819** | **0.9358** |
| 시간순 split | 0.8956 | **0.7589** | 0.6771 |

랜덤 split에서 test 데이터와 가장 가까운 train 데이터의 시간 거리는
**중앙값 0분, 최대 2분**이었습니다.

반면 시간순 split에서는 중앙값이 약 **2,449분**이었습니다.

예측 목표는 앞으로 30분 내 고장 여부이기 때문에
시간적으로 매우 가까운 데이터가 train과 test에 섞이면
서로 비슷한 미래 라벨을 공유하게 됩니다.

이 때문에 랜덤 split에서는 실제 운영 환경보다 쉬운 평가 문제가 만들어질 수 있었습니다.

반면 AI4I에서는 lag-1 자기상관이 거의 0에 가까웠고
랜덤/시간순 분할 차이도 상대적으로 작았습니다.

따라서 결론은 단순히
"시계열이면 무조건 시간순 split"이 아니라,

**시간적 의존성과 실제 운영 시점의 예측 구조를 고려하여 평가 방법을 정해야 한다**는 것입니다.

---

### 4.3 이상치를 무조건 삭제하면 실제 고장 신호도 사라질 수 있다

AI4I에서는 센서 이상치 일부가 실제 고장과 연결되어 있었습니다.

| 처리 | PR-AUC |
|---|---:|
| 이상치 행 삭제 안 함 | **0.8966** |
| IQR 이상치 행 삭제 | 0.8193 |
| 삭제하지 않고 플래그 추가 | 0.8852 |

IQR을 이용해 이상치를 단순 삭제하자 실제 고장 데이터까지 함께 제거되어 성능이 하락했습니다.

반대로 시뮬레이터에서는 매우 큰 센서 오작동이 존재했기 때문에
단순한 통계적 이상치와 실제 설비 이상이 서로 다른 의미를 가졌습니다.

따라서 이상치는 자동 삭제 대상이라기보다

**왜 이상한 값이 발생했는지를 확인한 뒤 처리 방법을 정해야 하는 데이터**라고 판단했습니다.

---

### 4.4 임계값은 비용 구조에 따라 달라진다

A6에서는 다음 비용을 가정했습니다.

- 고장을 놓침(FN): **800만원**
- 불필요한 점검(FP): **30만원**

이는 실제 기업 비용이 아니라 **분석을 위한 가정값**입니다.

| 기준 | 임계값 | 재현율 | 정밀도 | 총비용 |
|---|---:|---:|---:|---:|
| F1 최대 | 0.435 | 약 0.824 | 약 0.959 | 12,090만원 |
| 기본 0.5 | 0.500 | 약 0.824 | 약 0.959 | 12,090만원 |
| **비용 최소** | **0.060** | **0.929** | **0.444** | **7,770만원** |

가정한 비용 구조에서는 기본 임계값 0.5보다
0.06을 사용할 때 총비용이 약 **35.7% 감소**했습니다.

F1을 최대화하는 임계값과 비용을 최소화하는 임계값도 서로 달랐습니다.

따라서 실제 운영에서는 모델이 출력한 확률에 무조건 0.5를 적용하기보다
**고장 누락과 불필요한 점검의 실제 비용을 반영하여 임계값을 정해야 합니다.**

또한 상위 100건을 점검하는 실험에서는
전체 고장 85건 중 **72건**을 포함했습니다.

이는 "고장의 85%를 예방한다"는 의미가 아니라,
**모델 점수가 높은 100건 안에 실제 고장의 약 85%가 포함되었다는 의미**입니다.

---

### 4.5 센서 드리프트는 모델뿐 아니라 운영 경보에도 영향을 준다

CNC-02 온도 센서에 약 **0.35 K/day**의 드리프트를 주입했습니다.

회귀 기반으로 추정한 드리프트는 약 **0.346 K/day**로
주입값과 가까운 값을 탐지했습니다.

모델 성능에서는 보정 전후 차이가 크지 않았으며
보정이 항상 성능 향상으로 이어지는 것도 아니었습니다.

반면 고정된 센서 임계값을 사용하는 운영 경보에서는
센서가 조금씩 밀리는 것만으로도 경보 빈도가 크게 변할 수 있었습니다.

따라서 드리프트는 단순한 모델 성능 문제라기보다
**센서 품질과 운영 경보 신뢰성의 문제**로도 관리할 필요가 있습니다.

---

### 4.6 SECOM — 충분한 예측 성능을 확보하지 못했다

SECOM 데이터는 1,567행에 590개 센서가 있고
불량 사례는 104건뿐입니다.

정제 과정에서:

- 상수 센서 116개 제거
- 정제 후 446개 센서 사용
- 단변량 검정 p<0.05 센서 79개
- Bonferroni 보정 후 6개
- BH 보정 후 22개

를 확인했습니다.

시간순 평가에서 가장 높은 PR-AUC는 **0.0833**으로,
기준선 약 **0.0612**보다 조금 높은 수준에 그쳤습니다.

또한 주요 센서들의 효과 크기가 작았고,
상위 센서의 약 92%에서 시간에 따른 분포 이동이 관찰되었습니다.

따라서 이 결과를 억지로 좋은 성능으로 해석하지 않고

**현재 데이터만으로는 충분한 예측력을 확보하지 못했다**

고 판단했습니다.

개선을 위해서는 더 많은 불량 사례뿐 아니라
센서의 물리적 의미, 공정 단계, 설비 변경 이력 등의 추가 정보가 필요합니다.

## 5. 한계와 가정

### 데이터의 한계

- **시뮬레이터 데이터는 합성 데이터입니다.** 실제 설비에서 동일한 성능이 나온다고 볼 수 없습니다.
- 시뮬레이터의 고장 규칙이 결정론적이므로 실제 설비보다 예측이 쉬울 수 있습니다.
- 14일 × 3대의 데이터이므로 계절성과 장기적인 설비 열화를 충분히 반영하지 못합니다.
- AI4I는 실제 연속 센서 로그와 같은 형태의 시계열 데이터가 아닙니다.
- AI4I의 일부 고장 관련 라벨에는 서로 일치하지 않는 사례가 존재합니다.

### 방법의 한계

- **FN 800만원, FP 30만원이라는 비용은 실제 기업 비용이 아니라 가정값입니다.**
- 비용 구조가 바뀌면 최적 임계값 역시 달라집니다.
- 비용 기반 임계값을 test 데이터에서 탐색했기 때문에 낙관적 편향 가능성이 있습니다.
- 시간순 split을 한 번만 수행했습니다. 실제 적용에서는 walk-forward 방식 등의 반복 검증이 필요합니다.
- 드리프트 보정 전후 성능 차이가 작기 때문에 해당 차이를 보정 효과라고 단정할 수 없습니다.
- 다수의 롤링·파생 피처를 사용했으며 별도의 변수 선택 과정은 수행하지 않았습니다.

### 해석의 한계

- **상관관계는 인과관계를 의미하지 않습니다.**
- 변수 중요도는 모델이 예측에 많이 사용한 변수를 나타낼 뿐 설비 고장의 물리적 원인을 증명하지 않습니다.
- SECOM 결과는 현재 데이터와 분석 방법에서 충분한 성능이 나오지 않았다는 의미이며, 반도체 불량 예측 자체가 불가능하다는 의미가 아닙니다.

## 6. 다음 단계

1. **Walk-forward 검증 도입**  
   여러 시간 구간에서 반복 평가하여 모델 성능의 변동 범위를 확인

2. **실제 정비 비용 확보**  
   현재 가정으로 설정한 FN/FP 비용을 실제 정비·생산 손실 비용으로 교체

3. **임계값 결정용 validation 구간 분리**  
   train / validation / test 구조로 분리하여 test에서 임계값을 최적화하는 문제 개선

4. **장기간 데이터 수집**  
   현재 GitHub Actions 자동 수집 구조를 이용해 장기적인 센서 변화와 설비 열화 데이터 축적

5. **드리프트 모니터링 자동화**
