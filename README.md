# 설비 예지보전 (Predictive Maintenance) — 센서 파이프라인부터 대시보드까지

**CNC 밀링 설비의 센서 데이터를 수집·정제하고, 30분 내 고장을 예측합니다.**

수집 파이프라인(GitHub Actions 자동화)부터 대시보드 배포까지 전 구간을 구성했습니다.

## 30초 요약

| 항목 | 내용 |
|---|---|
| **문제** | 설비 고장을 **사후 감지**가 아니라 **30분 전 예지** — 계획 정비를 위한 고장 위험 예측 |
| **데이터** | ① 물리 기반 시뮬레이터(3대×14일, 55,591행) ② UCI AI4I 2020(10,000행) ③ UCI SECOM(1,567행×590센서) |
| **방법** | 수집 → 정제(9단계) → 피처 100개 → RandomForest → **시간순 split** → **비용 기반 임계값** |
| **결과** | 시뮬레이터 **PR-AUC 0.759**(기준선 약 0.237) / AI4I **PR-AUC 0.897**(기준선 0.034) / SECOM **PR-AUC 0.083**(기준선 0.061, 예측 성능 제한) |
| **핵심 발견** | 시뮬레이터에서 랜덤 split PR-AUC **0.982** → 시간순 split **0.759**로 하락. 시간적 의존성이 있는 데이터에서 랜덤 분할이 성능을 과대평가할 수 있음을 확인 |
| **한계** | 시뮬레이터는 합성 데이터이며 비용은 가정값. SECOM에서는 충분한 예측 성능을 확보하지 못함 |

## 왜 이 주제인가

스마트팩토리 환경에서는 설비 센서 데이터가 시간에 따라 연속적으로 수집되기 때문에 일반적인 정형 데이터 분석과 다른 문제가 발생할 수 있습니다.

이 프로젝트에서는 단순히 모델 성능을 높이는 것보다 **제조 센서 데이터를 다룰 때 발생할 수 있는 함정을 직접 검증하는 것**에 초점을 맞췄습니다.

|---|---|

| 센서 오작동 vs 진짜 이상 | [analysis/a4_outlier_trap.py](analysis/a4_outlier_trap.py) |
| **시간 누수 (temporal leakage)** | [analysis/a3_leakage.py](analysis/a3_leakage.py) ← **핵심** |
| 센서 드리프트 | [analysis/a5_drift.py](analysis/a5_drift.py) |

## 핵심 결과 3가지

### 1. 정확도만으로는 불균형 모델을 평가할 수 없다

AI4I 데이터의 고장률은 약 3.39%입니다.  
모든 데이터를 정상으로 예측해도 높은 정확도가 나오지만 고장을 하나도 찾아내지 못합니다.

| 모델 | 정확도 | 재현율 | PR-AUC |
|---|---:|---:|---:|
| 무조건 "정상" | **약 0.966** | 0.000 | 약 0.034 |
| 랜덤포레스트 | 약 0.982 | 약 0.576 | 약 0.789 |
| 랜덤포레스트 + 도메인 파생변수 | 약 0.993 | 약 0.824 | **0.897** |

→ 불균형 데이터에서는 정확도만 보는 대신 **PR-AUC와 고장률 기준선 대비 성능을 함께 확인**해야 합니다.

### 2. 시간 누수 — 랜덤 split이 만든 과대평가

같은 데이터와 모델을 사용하고 **데이터 분할 방식만 변경**해 비교했습니다.

| split | ROC-AUC | PR-AUC | F1@0.5 |
|---|---:|---:|---:|
| 랜덤 split | 0.9954 | **0.9819** | 0.9358 |
| 시간순 split | 0.8956 | **0.7589** | 0.6771 |

랜덤 split에서는 test 데이터와 가장 가까운 train 데이터의 시간 거리가 **중앙값 0분**이었습니다.

시뮬레이터의 예측 라벨은 앞으로 30분 내 고장 여부를 사용하기 때문에, 시간적으로 가까운 데이터를 무작위로 나누면 학습 구간과 평가 구간 사이의 의존성이 매우 커집니다.

반면 AI4I 데이터에서는 시뮬레이터와 달리 시간적 자기상관이 거의 없었고 랜덤/시간순 분할에 따른 차이도 상대적으로 작았습니다.

→ 단순히 "시계열이면 무조건 시간순 split"이라기보다 **시간적 의존성과 실제 운영 시점의 예측 구조를 고려해 분할 방법을 정해야 한다**고 판단했습니다.

### 3. 임계값 0.5가 항상 최적인 것은 아니다

고장을 놓쳤을 때의 비용을 **800만원**, 불필요한 점검 비용을 **30만원**으로 가정해 임계값별 총비용을 비교했습니다.

| 기준 | 임계값 | 재현율 | 정밀도 | 총비용 |
|---|---:|---:|---:|---:|
| 기본 임계값 | 0.50 | 약 0.824 | 약 0.959 | 12,090만원 |
| **비용 최소** | **0.06** | **0.929** | 0.444 | **7,770만원** |

가정한 비용 구조에서는 0.5보다 낮은 임계값을 사용할 때 고장 누락을 줄여 총비용을 낮출 수 있었습니다.

F1이 최대인 지점과 비용이 최소인 지점도 서로 달랐습니다.

→ 실제 운영에서는 고정된 0.5를 사용하는 대신 **고장 누락 비용과 점검 비용을 반영해 의사결정 임계값을 정해야 합니다.**

## 정제 처리 이력

원본 데이터를 바로 모델에 넣지 않고, 중복·물리 범위·시간축 문제를 단계별로 확인했습니다.

| 단계 | 행 수 | 증감 | 설명 |
|---|---:|---:|---|
| 0. 원본 수신 | 55,591 | — | 14개 일별 CSV |
| 3. 중복 제거 | 53,874 | -1,717 | `(machine_id, ts)` 기준 |
| 5. 물리범위 위반 → NaN | 53,874 | 0 | 행을 삭제하지 않고 해당 값만 NaN 처리 |
| 9. 시간축 재색인 | 60,479 | +6,605 | 통신 공백을 명시적인 NaN 행으로 표현 |

정제 후 학습용 데이터에서는 피처와 30분 미래 라벨을 생성할 수 없는 구간 등을 제외해 **53,811행**을 사용했습니다.

## 자동 수집 및 대시보드

GitHub Actions를 이용해 센서 데이터를 자동 수집하고 저장소의 `data/history/`에 일별 CSV 형태로 누적합니다.

수집 이후 모델 학습을 실행하고 `models/`의 성능 지표와 예측 결과를 갱신합니다.

Streamlit 대시보드는 저장된 결과를 읽어 다음 내용을 보여줍니다.

- 설비별 센서 추이와 고장 발생률
- 센서별 결측률
- 통신이 끊긴 수집 공백
- 모델 성능 및 비용 기반 임계값
- 프로젝트의 방법과 한계

대시보드에서 사용하는 데이터는 물리 기반 시뮬레이터로 생성한 **합성 데이터**입니다.

## 한계와 가정

### 데이터의 한계

- **시뮬레이터 데이터는 합성 데이터입니다.** 모델의 성능을 실제 제조 설비에 그대로 적용할 수 없습니다.
- 시뮬레이터의 고장 규칙이 결정론적이기 때문에 실제 설비보다 예측이 쉬울 수 있습니다.
- 14일 × 3대의 데이터이므로 계절성이나 장기적인 설비 열화를 충분히 반영하지 못합니다.
- AI4I 데이터에는 RNF 라벨과 전체 고장 라벨 사이에 일부 모순이 존재합니다.

### 방법의 한계

- **고장 누락 800만원, 불필요한 점검 30만원이라는 비용은 실제 기업 데이터가 아닌 가정값입니다.**
- 비용 구조가 달라지면 최적 임계값 역시 달라집니다.
- 비용 기반 임계값을 test 데이터에서 탐색했기 때문에 낙관적 편향 가능성이 있습니다.
- 시간순 split을 한 번만 사용했습니다. 실제 적용에서는 walk-forward 방식 등을 이용한 반복 검증이 필요합니다.
- 드리프트 보정 효과가 잡음에 의한 변화인지 명확히 구분하기 어렵습니다.

### 해석의 한계

- 상관관계가 있다고 해서 인과관계가 있다는 의미는 아닙니다.
- RandomForest의 변수 중요도는 모델이 예측에 많이 사용한 변수를 보여줄 뿐, 설비 고장의 물리적 원인을 증명하지 않습니다.
- SECOM의 낮은 성능은 **현재 사용한 데이터와 방법으로 충분한 예측력을 확보하지 못했다는 의미**이며, 반도체 공정 불량 예측 자체가 불가능하다는 의미는 아닙니다.

## SECOM에서 성능이 나오지 않은 이유

SECOM 데이터는 **1,567행에 590개 센서**가 존재하는 고차원·저표본 데이터이며 불량은 104건뿐입니다.

분석 과정에서:

- 상수 센서 116개 제거
- 정제 후 446개 센서 사용
- 단변량 검정 p<0.05 센서 79개
- Bonferroni 보정 후 6개
- BH 보정 후 22개
- 시간순 평가 PR-AUC **0.0833**
- 기준선 약 **0.0612**

를 확인했습니다.

또한 시간에 따라 센서 분포가 크게 이동하는 현상이 나타났습니다.

따라서 성능 수치를 억지로 높이기보다 **추가 불량 사례, 센서 의미에 대한 메타데이터, 공정 단계, 설비 변경 이력 등이 필요하다**고 판단했습니다.

## 무엇을 배웠나

1. **불균형 데이터에서는 정확도만으로 모델을 평가할 수 없다.**  
   PR-AUC와 고장률 기준선을 함께 확인해야 모델의 실제 분류 능력을 판단할 수 있었습니다.

2. **시간적 의존성을 무시한 데이터 분할은 성능을 과대평가할 수 있다.**  
   랜덤 split과 시간순 split을 직접 비교하면서 예지보전 문제에서 평가 방법 자체가 모델만큼 중요하다는 것을 확인했습니다.

3. **모델의 최적 기준은 평가 지표 하나로 결정되지 않는다.**  
   고장 누락과 불필요한 점검의 비용이 다르기 때문에 운영 목적에 맞는 임계값이 필요했습니다.

4. **좋은 결과가 나오지 않은 데이터도 분석 결과다.**  
   SECOM에서 낮은 성능을 확인하고, 표본 수·고차원성·분포 이동 등 성능을 제한하는 원인을 분석했습니다.
